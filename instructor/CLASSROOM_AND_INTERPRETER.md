# Practical delivery with Arabic interpretation

## Confirmed context

20 participants from Saudi Arabia; in-person delivery in Genoa; instructor delivery and repository materials in English; an Arabic interpreter will support the course. Learner technical proficiency and interpretation mode are not yet known. Do not infer technical skill or English proficiency from nationality.

## Classroom arrangement

Use 10 pairs for coding, ideally one laptop per participant and at least one per pair. Rotate keyboard and explanation roles every 10–15 minutes. For discussion, combine pairs into five groups of four. Ask each group for one finding rather than asking all 20 people to report individually.

Prepare a visible task card for every activity: goal, file to open, numbered actions, expected output and one check question. Provide a basic route and an optional extension. Display a timer. Ask pairs to signal ready, need help, or blocked using numbered cards or a show of hands; do not rely only on colour.

## Interpreter briefing before the course

Confirm whether interpretation is consecutive or simultaneous. This plan conservatively assumes consecutive interpretation. Meet the interpreter before delivery to review the day's vocabulary and the first demonstration. Provide the teaching guide, task instructions and glossary beforehand; confirm whether participants can follow English written task cards or need interpreter-reviewed Arabic copies.

The interpreter should keep Python keywords, variable names and file paths unchanged. Agree a consistent spoken Arabic term for each concept. All authored materials here remain in English; Arabic terminology and any learner translations require review by the interpreter.

Speak in short complete ideas, then pause. Avoid idioms and unexplained abbreviations. Do not speak over the interpreter. Keep the relevant code or chart visible while interpretation finishes; do not type new steps at the same time. Separate the instruction, interpretation, demonstration and learner action.

## Repeatable learning cycle

1. State one practical question (about 1 minute).
2. Explain the idea and allow interpretation (about 4 minutes).
3. Demonstrate one small operation and allow interpretation (about 5 minutes).
4. Pairs reproduce or adapt it (about 10–15 minutes).
5. Compare the expected result and interpret one finding (about 5 minutes).

These are planning estimates, not rigid limits. Use completion checks to adjust pacing. If interpretation takes longer, remove an optional extension rather than rushing the core exercise or consuming the break.

## Five-hour daily structure

| Minutes | Activity |
|---|---|
| 0–20 | Welcome, visual recap or diagnostic, pair setup |
| 20–50 | Short concept/demo cycle with interpretation |
| 50–90 | Pair lab A |
| 90–105 | Group feedback and interpretation |
| 105–120 | Break |
| 120–150 | Short concept/demo cycle with interpretation |
| 150–195 | Pair lab B |
| 195–210 | Break |
| 210–260 | Applied challenge in pairs |
| 260–285 | Five groups share one result each, with interpretation |
| 285–300 | Exit check and recap |

Total: 300 minutes including 30 minutes of breaks. Protected hands-on lab time: 135 minutes, half the 270 contact minutes. Interpretation is included within explanations, feedback and recap, not added on top. For five contact hours, add 30 minutes of supported practice and schedule breaks outside the contact hours.

## Logistics checklist

Confirm participant laptops, keyboard layouts, Python environments, projector readability, power outlets, room seating, interpreter audio arrangements and access to course files. Download everything before class. Check local venue timing and participant scheduling needs with the organiser rather than making assumptions. No participant records or personal data are required for the exercises.

## Contingencies

If a pair cannot run Python, use the saved output and ask them to interpret it while technical support resolves setup. If the cohort lacks Python basics, reduce independent coding and use guided changes to working examples after agreeing the scope with the organiser. If the cohort is advanced, use extensions and obtain specialist support for advanced questions.

End every lab by asking: What changed? What does it mean? What can we not conclude?
